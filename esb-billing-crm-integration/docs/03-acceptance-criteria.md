# 3. Критерии приёмки и тестирование

## 3.1 Критерии приёмки (Gherkin)

```gherkin
Функция: Смена тарифного плана через CRM

  Сценарий: Успешная смена тарифа сразу
    Дано абонент 77071234567 активен, тариф SMART_5, баланс 6000 ₸
    Когда оператор выбирает тариф SMART_10 (4990 ₸) с применением "сейчас"
    Тогда ESB возвращает 201 со статусом APPLIED
    И в биллинге у абонента тариф SMART_10
    И в топик billing.tariff.changed.v1 опубликовано событие с changeId
    И абонент получает SMS о смене тарифа

  Сценарий: Недостаточно средств
    Дано баланс абонента 1200 ₸
    Когда оператор выбирает тариф SMART_10 (4990 ₸)
    Тогда ESB возвращает 422 с кодом INSUFFICIENT_FUNDS
    И тариф в биллинге не изменился
    И событие в Kafka не публикуется

  Сценарий: Повторный запрос после таймаута не создаёт дубль
    Дано запрос с X-Request-Id = A уже успешно обработан
    Когда CRM повторно отправляет запрос с X-Request-Id = A
    Тогда ESB возвращает 200 с тем же changeId
    И биллинг повторно не вызывается
    И второе событие в Kafka не публикуется

  Сценарий: Биллинг недоступен
    Дано биллинг не отвечает дольше 10 секунд
    Когда оператор меняет тариф
    Тогда ESB возвращает 503 с кодом BILLING_UNAVAILABLE и заголовком Retry-After
    И оператор видит "Сервис временно недоступен, повторите позже"

  Сценарий: Смена с 1-го числа
    Когда оператор выбирает применение "с 1-го числа следующего месяца"
    Тогда ESB возвращает 201 со статусом SCHEDULED
    И effectiveDate равна 1-му числу следующего месяца
```

## 3.2 Уровни тестирования

| Уровень | Что проверяем | Кто |
| --- | --- | --- |
| Модульное | Маппинг JSON → XML, расчёт `ApplyDate`, валидация | Разработчик ESB |
| Интеграционное | ESB ↔ заглушка биллинга (SOAP mock), ESB → Kafka | QA, Postman / SoapUI |
| Системное (E2E) | CRM → ESB → биллинг → SMS на тестовом стенде | QA |
| Нагрузочное | 20 RPS, p95 ≤ 3 с | QA, JMeter |
| Приёмочное (UAT) | Сценарии 3.1 на реальных кейсах контакт-центра | Аналитик + бизнес |

## 3.3 Чек-лист негативных проверок API

- [ ] `msisdn` в неверном формате (`8707...`, 10 цифр, буквы) → `400`
- [ ] Без `X-Request-Id` → `400`
- [ ] `newTariffCode` отсутствует или не существует → `400` / `422 TARIFF_NOT_AVAILABLE`
- [ ] `effectiveMode` вне enum → `400`
- [ ] Без токена или с истёкшим токеном → `401`
- [ ] Абонент заблокирован → `404 SUBSCRIBER_NOT_FOUND`
- [ ] Два параллельных запроса на один номер → один `201`, второй `409`
- [ ] Номер замаскирован в логах ESB
